# RepairCalc — микросервис умных калькуляторов ремонта

SpbTechRun 2026 · кейс №1 «Микросервис умных калькуляторов ремонта и стоимости работ».

Пользователь выбирает объект, тип ремонта и помещения и получает смету: какие товары каталога купить, сколько
и за сколько, с учётом специфики комнаты (влажность, назначение, нагрузка). В карточке товара сервис считает
количество под размеры стены или комнаты и добавляет всё, что нужно для работы. ML-модель сама относит товары
каталога к видам работ, поэтому тысячи SKU не нужно размечать вручную.

## Что сделано

| Требование кейса | Где |
|---|---|
| Общий калькулятор: объект + тип ремонта → смета (пол, стены, обои, электрика) | `POST /api/v1/calc/general`, вкладка «Смета» |
| Расчёт на карточке товара под размеры | `POST /api/v1/product/{id}/calc`, виджет [static/widget.js](static/widget.js) |
| ML-матчинг товаров к видам работ (multi-label, F1) | [app/ml/](app/ml/), отчёт [reports/metrics_synthetic.md](reports/metrics_synthetic.md) |
| Учёт специфики комнаты (влага, назначение) | [app/calc/plan.py](app/calc/plan.py), [app/recommend.py](app/recommend.py) |
| RAG-пояснения «почему эти материалы» | [app/rag.py](app/rag.py), [data/knowledge/](data/knowledge/) |
| Мини-админка привязки с ML-подсказками | вкладка «Админка», `/api/v1/admin/*` |
| Извлечение параметров из текстового запроса | `POST /api/v1/calc/text`, [app/nlp.py](app/nlp.py) |
| Полный цикл: загрузка каталога → ML-разметка | `POST /api/v1/admin/sync`, [scripts/ingest_catalog.py](scripts/ingest_catalog.py) |
| Закрытый контур, локальная модель | e5 (MIT) локально + Ollama (Qwen2.5, Apache-2.0); без LLM всё работает на правилах |
| Справочник видов работ, правила, тестовая выборка, методика | [docs/taxonomy.md](docs/taxonomy.md), [docs/methodology.md](docs/methodology.md) |

## Быстрый старт

```bash
make setup      # venv + зависимости
make model      # скачать multilingual-e5-small в models/hf (один раз, ~470 МБ)
make data       # тестовый каталог + эталонная разметка (детерминированно, seed 42)
make train      # обучение модели -> models/matcher.joblib (~20 с)
make run        # http://localhost:8000  (UI: /ui/, Swagger: /docs)
make eval       # воспроизводимая оценка -> reports/metrics_synthetic.md (~6 мин)
make test       # 28 тестов: эталонные расчёты, API, парсер
```

Локальная LLM (необязательно): `ollama pull qwen2.5:7b-instruct`, после чего сервис сам начнёт использовать
её для пояснений и разбора текста (`RC_OLLAMA_URL`, `RC_OLLAMA_MODEL`). Развёртывание на сервере с GPU —
`docker compose up -d` (см. [docker-compose.yml](docker-compose.yml)).

## Демо-сценарий для защиты

1. «Смета» → ссылка «квартира → капремонт → санузел 6 м², высокая влажность». В смете: влагостойкий ГКЛВ,
   гидроизоляция с заведением на стены, плитка с запасом на подрезку, затирка, IP44, вентилятор, тёплый пол,
   итоговая стоимость и пояснение «почему эти материалы».
2. «Карточка товара» → плитка → ширина и высота стены → количество упаковок, цена, клей, затирка и грунтовка
   «в корзину». Тот же расчёт встроен виджетом в [пример страницы магазина](static/product.html).
3. «Админка» → «Синхронизировать»: 155 новых товаров загружаются со стенда и размечаются за ~1 с.
   «Новый товар» → ML предлагает вид работ, класс материала и помещения.
4. «Качество ML» → метрики по трём протоколам, F1 по видам работ, абляция, производительность.

Презентация: [docs/RepairCalc.pptx](docs/RepairCalc.pptx), 14 слайдов с заметками докладчика.
Она собирается из актуальных метрик командой `python -m scripts.make_presentation`.

## Структура

```
app/            сервис: API, каталог, ML, расчёт, подбор, RAG, мок стенда
  ml/           матчинг (matcher.py), признаки (features.py), эмбеддинги, датасет
  calc/         план работ по помещениям, формулы расхода, сборка сметы
static/         UI (без сборки и CDN), виджет для карточки товара
data/           справочник видов работ, база знаний, каталог, эталонная разметка
scripts/        генерация каталога, обучение, загрузка со стенда, выборка для перепроверки, лицензии
eval/           оценка качества, согласованность разметчиков
docs/           таксономия, методика, архитектура, письмо организаторам, презентация, лицензии
tests/          эталонные расчёты (MAE = 0), API, парсер
```

## Данные

**Реальный каталог Максидома** (выгрузка организаторов, 88 790 товаров + YML-фид СПб) — основной набор,
см. [docs/real_data.md](docs/real_data.md). Сырые данные в репозиторий не входят: положите
`products_final.json` и `export_yandex_spb.xml` в `data/real/raw/` и выполните
`python -m scripts.build_real_catalog` (≈ 8 с). Эталон «категория → виды работ» —
[scripts/real_category_map.py](scripts/real_category_map.py), таблица для проверки — `data/real/category_map.csv`.
Набор выбирается переменной `RC_DATASET=real|synthetic` (по умолчанию real, если каталог собран).

**Синтетический каталог** (собран до получения данных) в формате API стенда: 1 140 карточек,
124 подтипа товаров, 26 видов работ, товары под несколько видов работ, неоднозначные товары и товары вне ремонта.
Бренды вымышленные. Реальный каталог подключается без изменения архитектуры:
`python -m scripts.ingest_catalog --base-url <стенд>`, после чего размечается образец по
[правилам](docs/taxonomy.md) и выполняется `make train eval`.
