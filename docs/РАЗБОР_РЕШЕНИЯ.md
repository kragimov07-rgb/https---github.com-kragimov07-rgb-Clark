**Желательно (за доп. баллы):** пояснения «почему эти материалы», админка с ML-подсказками, разбор запроса текстом.

**Ограничение:** система должна работать в закрытом контуре — только локальные модели, никаких внешних API.

**Итог: всё обязательное и всё желательное сделано.**

## 2. Решение простыми словами

### Что мы построили

**RepairCalc** — веб-сервис (сайт + API), который работает на **реальном каталоге Максидома — 88 790 товаров**.
Каталог дали организаторы, плюс мы подтянули с сайта Максидома фид с ценами и наличием по Петербургу.

Три сценария:

| Сценарий | Что делает пользователь | Что получает |
|---|---|---|
| **Смета** | выбирает «квартира, капремонт, санузел 6 м²» | список реальных товаров: какой, сколько, почём, итог ~100 тыс. ₽, пояснение «почему» |
| **Карточка товара** | открывает плитку, вводит «стена 3,2 × 2,7» | «6 упаковок, 11 262 ₽» + клей, затирка, грунт к ней |
| **Админка** | загружает новые товары в каталог | ML сам говорит, к каким работам относится товар и для каких комнат подходит |

### Как это работает внутри (4 блока)

**Блок 1. Справочник видов работ.** Мы сами составили список из **26 видов ремонтных работ** в порядке, как делается
ремонт: подготовка (демонтаж, грунтовка) → черновые (стяжка, штукатурка, гипсокартон, гидроизоляция) → инженерка
(электрика, сантехника, отопление, вентиляция) → чистовая отделка (плитка, покраска, обои, ламинат) → завершающие
(двери, плинтусы). Плюс 7 правил: когда товар относится к виду работ (например, «грунтовка относится к 6 работам сразу —
перед покраской, обоями, плиткой, шпаклёвкой, штукатуркой»).

**Блок 2. ML-модель (главное «умное» место).** На вход — карточка товара (название, категория, описание, характеристики).
На выход — к каким видам работ относится товар (может быть несколько), класс материала (плитка, клей, краска…)
и подходящие комнаты. Модель **гибридная**, из 4 частей:
1. **Классический ML** (TF-IDF + логистическая регрессия) — хорошо узнаёт товары по словам.
2. **Нейросетевые эмбеддинги** (локальная модель multilingual-e5) — понимает смысл, а не только слова.
3. **Zero-shot по справочнику** — сравнивает товар с описанием каждого вида работ («затирка» похожа на «затирка для швов»
   → это укладка плитки). Помогает с товарами, которых модель никогда не видела.
4. **«Шлюз»** — отсекает товары не для ремонта (65% каталога — это сад, посуда, мебель, бытовая техника).

Как учили: размечать 88 тысяч товаров руками невозможно, поэтому мы разметили **категории** каталога
(1 083 ремонтные категории из 2 375) — товар получает разметку своей категории; для смешанных категорий (саморезы,
герметики, шпатели) — уточняющие правила по названию.

**Блок 3. Калькулятор (математическая модель).** Для каждой комнаты строится план работ (что делать при таком типе
ремонта), для каждой позиции подбирается товар и считается количество по формулам:
- **Плитка/ламинат:** площадь × (1 + запас на подрезку 10%) / площадь упаковки → округляем вверх.
- **Обои:** сколько полос нужно по периметру, сколько полос выходит из рулона с учётом высоты и раппорта → рулоны.
- **Краска:** площадь × расход л/м² × 2 слоя / объём банки.
- **Смеси (клей, штукатурка, стяжка):** площадь × расход кг/м² на мм × толщина / вес мешка.
- **Гидроизоляция:** пол + 30 см на стены, 2 слоя.
- **Кабель:** число розеток/выключателей/светильников × 7 м + 10 м запаса.

Расход берётся **из карточки товара**, если он там указан; если нет — типовая норма (с пометкой в смете).
Каждая позиция сметы показывает формулу — жюри видит «математическую модель».

**Блок 4. Подбор товара под комнату.** Из подходящих товаров выбирается лучший:
- жёсткие правила комнаты (санузел → только влагостойкое и розетки IP44; кухня и прихожая → ламинат ≥ 33 класса);
- ранжирование (уверенность модели, наличие, ценовой сегмент под тип ремонта);
- **выгодная фасовка:** система считает итоговую стоимость позиции и не выберет 14 банок по 1,5 кг, если есть мешок 20 кг.

### Результаты (цифры, которые надо помнить)

| Что | Цифра |
|---|---|
| Каталог | **88 790** реальных товаров Максидома |
| Точность ML на новых товарах | **micro-F1 = 0,97** (требование ≥ 0,8 ✅) |
| Точность на категориях, которые модель вообще не видела | **0,78** (простая модель — 0,72) |
| Товары не для ремонта, правильно отсечённые | **95–99%** |
| Точность формул | **0 ошибок** на 16 расчётах, проверенных вручную |
| Скорость | смета ~0,1 с, разметка товара 2 мс, запуск сервиса 12 с |
| Тесты | **35 автотестов**, все проходят |

Мы сделали три сценария на одном движке. Первый — смета: выбираете тип жилья, тип ремонта и комнаты, получаете список
товаров с количеством и ценой. Второй — учёт специфики комнаты: влажность, назначение, нагрузка. Третий — расчёт прямо

## 4. Ответы на вопросы жюри (коротко, своими словами)

**«Как вы получили разметку, если её не дали?»**
Разметили категории каталога по нашему справочнику — 1 083 ремонтные категории. Товар получает разметку категории,
для смешанных категорий — уточняющие правила по названию.

**«А модель не выучила просто категории?»**
Поэтому мы отдельно проверили режим, где в тесте только категории, которых модель не видела. Там 0,78 — модель
понимает товар по названию и характеристикам, а не только по категории.

**«Почему на незнакомых категориях меньше 0,8?»**
Это самый жёсткий тест — модель не видела ни одного товара такой категории. Основной сценарий (новые товары) — 0,97.
Для неуверенных товаров есть очередь проверки и локальная LLM, которая уточняет такие случаи.

**«Где модель ошибается?»**
Где вид работ представлен 1–2 необычными категориями: демонтаж (мешки, ломы), потолки. Часть ошибок — спорные
случаи разметки.

**«Откуда нормы расхода?»**
Из карточки товара, если указаны. Если нет — типовые нормы из сводов правил и данных производителей, с пометкой.

**«Почему выбран именно этот товар?»**
Подходит по виду работ и требованиям комнаты, есть в наличии, подходит по цене под тип ремонта, и итоговая стоимость
позиции выгоднее (учитываем фасовку). Альтернативы показаны под каждой позицией.

**«Как это работает без интернета?»**
Все модели локальные: модель эмбеддингов на процессоре, языковая модель — через Ollama на видеокарте заказчика.
Без языковой модели всё тоже работает — пояснения собираются из базы знаний.

**«Как подключить к сайту?»**
Это отдельный сервис с REST API. На страницу товара — две строки кода виджета. Каталог синхронизируется через API.

**«Как добавить новый товар?»**
Загружается через API — модель размечает его за 2 миллисекунды, неуверенные попадают в очередь админки.

Если не знаешь ответ — нормально сказать: «Хороший вопрос, это следующий шаг развития: …» (например, «обучим
на реальных заказах коэффициенты отходов» или «доразметим слабые виды работ»).

## 5. Словарик (если жюри спросит термин)

| Термин | Простыми словами |
|---|---|
| **ML-матчинг** | модель сопоставляет товар с видами работ |
| **Многометочная классификация** | у товара может быть несколько правильных ответов сразу (грунтовка → 6 работ) |
| **F1** | оценка точности от 0 до 1; учитывает и «не ошибиться», и «ничего не пропустить». 0,8 — требование, у нас 0,97 |
| **micro-F1 / macro-F1** | micro — по всем товарам вместе; macro — среднее по видам работ (честнее для редких работ) |
| **Baseline** | простая модель для сравнения (TF-IDF + логрегрессия) |
| **Эмбеддинги** | превращение текста в числа так, что похожие по смыслу тексты получаются похожими числами |
| **Zero-shot** | модель распознаёт то, чему её специально не учили, — через сравнение с описанием вида работ |
| **TF-IDF** | способ превратить текст в числа по важности слов |
| **RAG** | поиск по базе знаний + генерация пояснения на её основе |
| **LLM / Ollama** | языковая модель (как ChatGPT), запущенная локально; Ollama — программа для её запуска |
| **Закрытый контур** | система работает без интернета и внешних сервисов |
| **nDCG@10** | насколько правильные товары оказываются наверху списка |

## 6. Как запустить на защите

На этом ноутбуке всё уже собрано:
```bash
cd ~/СберХак/repaircalc
make run
```
Подождать 10–15 секунд, открыть в браузере **http://localhost:8000/ui/**.
Если что-то сломалось на защите — показывать скриншоты из `docs/img/` (они же в слайдах 5, 6, 13).

**На другом компьютере** (если демо будет не с этого ноутбука) нужно собрать с нуля — см. раздел «Запуск с нуля»
в `README.md` (нужны файлы данных организаторов; обучение ≈ 10–20 мин). Надёжнее взять на защиту этот ноутбук.

**Необязательно, но красиво:** установить Ollama (ollama.com), выполнить `ollama pull qwen2.5:7b-instruct` и перезапустить
`make run` — пояснения в смете станут живым текстом от локальной языковой модели.
