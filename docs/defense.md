# Защита: сценарий и ответы на вопросы жюри

## Перед выходом (за 30 минут)

1. `make run` → дождаться `RepairCalc ready` (12 с при готовом кэше; без кэша ≈ 3 мин).
2. Открыть вкладки: `http://localhost:8000/ui/`, `http://localhost:8000/docs`, `http://localhost:8000/ui/product.html?id=<id плитки>`.
3. Прогнать демо один раз целиком (прогрев). Если сеть на площадке нестабильна — всё работает локально, интернет не нужен.
4. План Б: скриншоты в `docs/img/` и слайды 5, 6, 13 с ними же.

## Тайминг выступления (≈ 7 минут)

## Демо: что нажимать

1. **Смета** → «квартира → капремонт → санузел 6 м², высокая влажность». Показать: ГКЛВ, гидроизоляцию
   «+30 см на стены», формулу у плитки (запас 10%, упаковки по 1,79 м²), розетки IP44, пояснение «почему».
2. **Карточка товара** → первая плитка → 3,2 × 2,7 → «6 уп.» + клей, затирка, грунт «в корзину».
   Ссылка «пример карточки с виджетом» — тот же расчёт на странице магазина двумя строками кода.
3. **Админка** → «Взять реальный товар, которого модель не видела» (2–3 раза: попадутся и ремонтные, и нет)
   → «Синхронизировать» — 500 товаров со стенда за ~3 с.
4. **Качество ML** — таблица трёх протоколов.

## Вероятные вопросы и ответы

**Как вы получили F1 ≥ 0,8, если заказчик не дал разметку?**
Разметили 1 083 ремонтные категории каталога по правилам справочника и уточнили смешанные категории правилами
по названию. Модель проверяли тремя протоколами; на новых товарах — 0,97. Отдельно — протокол «незнакомые
категории», где разметку из категории не выучить: там 0,78 против 0,72 у baseline.

**Не выучила ли модель просто таблицу «категория → вид работ»?**
На случайном разбиении — частично да, это и есть полезное поведение в production. Поэтому основной честный
протокол — GroupKFold по категориям: в тесте категории, которых модель не видела, и она определяет виды работ
по названию, описанию и характеристикам. Гибрид там лучше baseline на всех метриках.

**Почему гибрид хуже baseline на знакомых категориях (0,974 против 0,991)?**
Zero-shot компонент сглаживает уверенные предсказания ради обобщения. Мы выбрали устойчивость к новым
товарам и категориям: +5,8 п.п. micro-F1 и +11,5 п.п. macro-F1 на незнакомых категориях.

**Где модель ошибается?**
Виды работ, представленные 1–2 непохожими категориями: демонтаж (мешки, ломы), потолки, обои, комплектующие ГКЛ.
Часть «ошибок» — спорная разметка (фасадная сетка, мебельные петли). Для этого есть очередь «на границе порога»
в админке (≈ 5 тыс. товаров) и ручная привязка, которая важнее ML.

**Как обрабатываются товары под несколько видов работ?**
Задача многометочная: one-vs-rest + свой порог на каждый вид работ. 3 239 таких товаров в каталоге; F1 на них
0,94–0,97 для известных категорий.

**Откуда нормы расхода? Что если в карточке нет расхода?**
Расход берётся из карточки, если значение правдоподобно (с переводом г → кг, «м² на пачку» → площадь оклейки);
иначе — типовая норма из базы знаний (СП 71.13330, СП 29.13330, данные производителей) с пометкой в смете.
16 эталонных расчётов вручную — MAE = 0 (`tests/test_formulas.py`).

**Почему смета выбрала этот товар, а не другой?**
Кандидаты — товары нужного вида работ и класса; фильтр позиции по названию; ограничения помещения
(влагостойкость, IP44, класс износостойкости); ранжирование (уверенность ML, наличие, ценовой сегмент под тип
ремонта по цене за кг/л/м²); итоговый выбор — «качество минус штраф за переплату», поэтому мешок 20 кг, а не
14 банок по 1,5 кг. Альтернативы показаны под каждой позицией.

**Как это работает в закрытом контуре?**
Эмбеддинги multilingual-e5-small (MIT) локально на CPU, LLM — Ollama с Qwen2.5 (Apache-2.0) на RTX 3090
заказчика. Внешних API нет. Без LLM всё работает: разбор текста и пояснения на правилах и шаблонах.

**Сколько ресурсов нужно?**
Сервис ≈ 3 ГБ RAM на весь каталог, разметка товара 2 мс, смета 60–150 мс, обучение 8–20 мин на ноутбуке M1 Pro.

**Как подключить к сайту на Bitrix?**
REST/JSON-микросервис; в карточку — виджет `<div data-repaircalc-product="ID">` + `<script src=".../widget.js">`;
каталог синхронизируется через API стенда (`/api/v1/admin/sync`) или выгрузку.

**Как добавить новый товар или категорию?**
Загрузка через API — товар размечается автоматически (2 мс). Новая категория распознаётся благодаря zero-shot
компоненту; если модель не уверена — товар попадает в очередь админки.
