# Методика оценки ML-матчинга «товар → виды работ»

Полные отчёты (F1 по каждому виду работ, примеры ошибок, производительность):
[reports/metrics_real.md](../reports/metrics_real.md) — реальный каталог Максидома (основной),
[reports/metrics_synthetic.md](../reports/metrics_synthetic.md) — синтетический каталог (с абляцией компонентов).

Воспроизведение на реальных данных:
```bash
python -m scripts.build_real_catalog          # каталог + фид -> data/real (≈ 8 с)
python -m scripts.train                        # модель -> models/real (≈ 8–20 мин на M1 Pro)
python -m eval.evaluate --folds 3 --no-ablation   # отчёт -> reports/metrics_real.md (≈ 1 ч)
```

## 1. Постановка

- **Задача:** многометочная классификация. Каждому товару присваивается множество видов работ из
  [справочника](taxonomy.md) (26 классов); пустое множество — «не относится к ремонту помещений».
- **Вход:** карточка товара — название, путь в дереве категорий, описание, маркетинговое описание, характеристики.
- **Выход:** набор видов работ, вероятность по каждому (для ранжирования), класс материала (для формулы расчёта),
  подходящие помещения.

## 2. Данные и эталон

| Набор | Объём | Назначение |
|---|---|---|
| `data/real/products.json` + `data/real/labels.csv` | 86 072 товара, 2 358 категорий | обучение и кросс-валидация |
| `data/real/new_products.json` + `labels_new.csv` | 2 661 товар (3%, случайная отложенная выборка) | проверка на новых товарах; в обучении не участвует |
| `data/real/category_map.csv` | 2 375 категорий | таблица «категория → виды работ, класс» для проверки |

Эталон построен по правилам R1–R7 справочника **на уровне категорий** каталога (1 083 ремонтные категории
размечены вручную) с уточняющими правилами по названию для смешанных категорий — подробно в
[real_data.md](real_data.md). Состав: 30 353 товара относятся к ремонту, 3 239 — к нескольким видам работ,
55 719 — вне ремонта (сад, посуда, мебель, бытовая техника, ...). Это реальная структура ассортимента:
модель должна не только найти виды работ, но и не навязывать их нерелевантным товарам.

## 3. Протоколы

| Протокол | Как устроен | Что проверяет |
|---|---|---|
| **K-fold по товарам** (3 фолда) | KFold(shuffle, seed 42) | качество на новых SKU в известных категориях — основной производственный сценарий |
| **Новые товары** | обучение на всём каталоге, тест на отложенной выборке | воспроизводимость на новых данных (как при загрузке со стенда) |
| **Незнакомые категории** (3 фолда) | GroupKFold по категориям: в тесте только категории, которых модель не видела | обобщение «по смыслу»: новые категории в каталоге, товары без категории, ошибки рубрикации |

Пороги подбираются только на out-of-fold предсказаниях внутри обучающей части, поэтому тестовые товары
не участвуют ни в обучении, ни в подборе порогов.

**Почему протокол «незнакомые категории» обязателен.** Эталон выведен из категорий, а путь категории входит
в признаки. На случайном разбиении модель может выучить таблицу «категория → виды работ» — это полезно
в production, но не доказывает понимание смысла. В протоколе по категориям виды работ приходится определять
по названию, описанию и характеристикам — это честная оценка способности «учитывать смысл и характеристики
товаров, а не только буквальные совпадения».

## 4. Метрики

| Метрика | Что показывает | Цель |
|---|---|---|
| **micro-F1** (основная) | качество по всем парам «товар — вид работ» | ≥ 0,8 |
| macro-F1 | качество на редких видах работ | — |
| nDCG@10, MAP | ранжирование товаров внутри вида работ (то, что видит пользователь в подборе) | — |
| доля верных «вне ремонта» | модель не навязывает виды работ нерелевантным товарам | — |
| multi-label micro-F1 | качество на товарах с ≥ 2 видами работ | — |
| accuracy класса материала | корректность выбора формулы расхода (по ремонтным товарам) | — |

## 5. Результаты на реальном каталоге

| Модель | Протокол | micro-F1 | macro-F1 | nDCG@10 | MAP | вне ремонта | multi-label F1 | класс материала |
|---|---|---|---|---|---|---|---|---|
| baseline (TF-IDF + LR) | 3-fold по товарам | 0,991 | 0,979 | 1,000 | 0,996 | 0,995 | 0,991 | 0,995 |
| baseline | новые товары | 0,983 | 0,966 | 1,000 | 0,994 | 0,994 | 0,971 | 0,999 |
| baseline | незнакомые категории | 0,723 | 0,510 | 0,753 | 0,623 | 0,963 | 0,298 | 0,616 |
| **hybrid** | 3-fold по товарам | **0,974** | 0,954 | 1,000 | 0,982 | 0,989 | 0,967 | 0,982 |
| **hybrid** | новые товары | **0,966** | 0,950 | 0,995 | 0,986 | 0,989 | 0,936 | 0,975 |
| **hybrid** | незнакомые категории | **0,781** | 0,625 | 0,834 | 0,663 | 0,950 | 0,418 | 0,681 |

**Производительность** (Apple M1 Pro, 16 ГБ, 4 процесса): обучение гибрида 7,5 мин (на 50 тыс. товаров после
прореживания нерелевантных), инференс 2 мс на товар, разметка всего каталога 86 тыс. товаров ≈ 3 мин
(затем кэшируется — старт сервиса 12 с), пиковая память при оценке ≈ 4 ГБ, полная оценка ≈ 56 мин.

## 6. Интерпретация

1. **Цель micro-F1 ≥ 0,8 достигнута** в основном сценарии (новые товары известных категорий: 0,97–0,98).
2. **Гибрид vs baseline.** На незнакомых категориях гибрид лучше на всех метриках: micro-F1 +5,8 п.п., macro-F1
   +11,5 п.п., nDCG@10 +8,1 п.п., multi-label F1 +12 п.п., класс материала +6,5 п.п. На знакомых категориях
   baseline чуть выше (0,991 против 0,974): zero-shot компонент сглаживает уверенные предсказания ради обобщения.
   В production разумно использовать гибрид — он устойчивее к новым товарам и категориям.
3. **Слабые места на незнакомых категориях**: виды работ, представленные в каталоге 1–2 категориями, которые
   не похожи на остальные (демонтаж — мешки и ломы; потолки — плинтусы и плитки; обои; ГКЛ-комплектующие).
   Типичные ошибки — в [отчёте](../reports/metrics_real.md#примеры-ошибок-незнакомые-категории): часть из них —
   спорные случаи разметки (фасадная сетка, мебельные петли, коронки).
4. **Что пробовали и отклонили** (подвыборка 30 тыс. товаров, 3 фолда, micro-F1 случайное / незнакомые категории):
   текущая конфигурация — 0,965 / 0,775; больший вес zero-shot и kNN (0,45 / 0,30) — 0,956 / 0,769; подбор порогов
   на фолдах по категориям — 0,952 / 0,763. Оба варианта хуже на обоих протоколах, оставлена текущая.
5. **Как улучшать дальше:** разметка ещё 200–300 товаров в слабых видах работ; локальная LLM (Ollama) для товаров
   «на границе порога» (≈ 5 тыс. в каталоге — очередь в админке); расширение описаний видов работ в справочнике.

## 7. Синтетический каталог (приложение)

До получения реальных данных модель отлаживалась на синтетическом каталоге (1 140 товаров, 124 подтипа):
micro-F1 0,970 по товарам, 0,988 на новых товарах, 0,676 на незнакомых подтипах. Абляция на нём показала, что
основной вклад в обобщение даёт zero-shot сопоставление со справочником (без него micro-F1 на незнакомых
подтипах 0,575, nDCG@10 0,630 против 0,812) — [отчёт](../reports/metrics_synthetic.md).

## 8. Независимая проверка

1. Заказчик передаёт размеченную выборку: карточки в формате API стенда (или выгрузки `products_final.json`) и CSV
   `id;work_types` с кодами справочника через «|». Если у заказчика своя таксономия — таблицу соответствия.
2. Запуск `python -m eval.evaluate` с путями к выборке (протокол «новые товары»); отчёт формируется автоматически.
3. Для согласованности разметчиков: `python -m scripts.review_sample` и `python -m eval.agreement` (каппа Коэна).
