# Реальный каталог Максидома: данные и эталонная разметка

## Источники

| Источник | Что содержит | Где |
|---|---|---|
| Выгрузка организаторов `products_final.json` (Яндекс Диск из вики хакатона) | 88 790 карточек: название, описания, характеристики (8,8 на товар), бренд, страна, листовая категория (2 375), цена, единица продажи | `data/real/raw/` |
| YML-фид сайта `export_yandex_spb.xml` (ссылка в вики хакатона) | дерево категорий (3 326 узлов), цена и наличие по Санкт-Петербургу, фото, параметры | `data/real/raw/` |

**Соединение источников.** В фиде нет `cod_good`, но код товара есть в URL оффера: `/catalog/.../1000002278/`.
По нему к фиду присоединяются 56 555 карточек: у них есть цена по СПб и признак наличия. Путь в дереве категорий
восстанавливается по `categoryId` оффера, а если оффера нет — по имени листовой категории (2 360 из 2 375 совпадают).

Сборка: `python -m scripts.build_real_catalog` (≈ 8 с) → `data/real/products.json` в формате сервиса.

## Чем реальные данные отличаются от формата из кейса

- Нет остатков по складам и `result_price`: цена берётся из фида (СПб), наличие — признак `available`.
- Нет `package_area`: площадь упаковки извлекается из характеристик «Площадь покрытия упаковкой» / «В упаковке».
- Характеристики без единиц измерения: «Вес 5000» (граммы) и «Вес 5» (кг), «Расход 2,1-5,2», «Длина 2200» (мм).
  Нормализация — `app/catalog.py::attributes`: диапазоны → середина, единицы по правдоподобию значения,
  отрицания («не влагостойкие»), извлечение из названия. В формулах — проверка правдоподобия расхода
  с переводом г → кг и «м² на литр» → л/м², иначе типовая норма с пометкой в смете.
- 65% ассортимента не относится к ремонту помещений (сад, посуда, текстиль, мебель, бытовая техника, авто).

## Эталонная разметка

Размечать 88 790 SKU по одному нереалистично, поэтому разметка выполнена **на уровне категорий каталога**
(как работала бы админка магазина) по правилам R1–R7 справочника:

1. **1 083 категории ремонтных веток** просмотрены вручную; каждой назначены виды работ и класс материала
   ([scripts/real_category_map.py](../scripts/real_category_map.py), таблица для проверки —
   `data/real/category_map.csv`).
2. **Уточняющие правила на уровне товара** для смешанных категорий: саморезы (по ГКЛ → монтаж гипсокартона,
   по дереву → панели / двери / плинтусы), ровнители (наливной пол или стяжка), шпатели (зубчатые → плитка),
   герметики (санитарные → + сантехника, акриловые → + откосы), средства для обоев (для снятия → + демонтаж),
   комплектующие ГКЛ (подвесы → + потолки, серпянка → + шпаклевание, маяки → штукатурка и стяжка).
3. **Неремонтные ветки** (сад, посуда, мебель, бытовая техника, ...) и неремонтные категории внутри ремонтных
   (фасад, кровля, водостоки, шторы, лаки для дерева, фильтры-кувшины, газовое оборудование) — без меток (R5).
4. «Ликвидация остатков» (57 товаров, смешанный ассортимент) не размечается — это пример товаров,
   которые размечает только модель.

Итог: 88 733 размеченных товара, из них **31 283 относятся к ремонту**, 3 331 — к нескольким видам работ.
Отложенная выборка «новых товаров» — 3% (2 661), в обучении не участвует.

### Что обязательно сделать команде

Разметку категорий выполнил один человек. Перед защитой её нужно перепроверить:

- пройти `data/real/category_map.csv` (по убыванию числа товаров) и подтвердить или исправить виды работ,
  заполнив колонку `verified_by`;
- независимо разметить двумя участниками выборку из 300 товаров (`python -m scripts.review_sample`) и посчитать
  согласованность (`python -m eval.agreement`).

### Почему важен протокол «незнакомые категории»

Метки выведены из категорий, а путь категории входит в признаки модели. На случайном разбиении модель может
просто выучить таблицу «категория → виды работ», поэтому основной протокол — **GroupKFold по категориям**:
в тесте только категории, которых модель не видела, и виды работ приходится определять по названию,
описанию и характеристикам. Ровно эта ситуация возникает, когда в каталоге появляется новая категория или
когда нужно разметить товар без категории.
